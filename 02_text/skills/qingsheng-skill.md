# /qingsheng-upgrade — 升级情圣技能

升级 qingsheng-skill 到最新版本。

## 触发方式

用户说 `/qingsheng-upgrade` 或"升级情圣技能"时执行本流程。

---

## 执行步骤

### Step 1：检测安装位置和类型

按优先级查找安装目录：

```
~/.claude/skills/qingsheng-skill/ ← global（优先）
.claude/skills/qingsheng-skill/ ← local（项目级）
```

用 Bash 工具：
```bash
# 检测 global
ls ~/.claude/skills/qingsheng-skill/VERSION 2>/dev/null && echo "global"
# 检测 local 
ls .claude/skills/qingsheng-skill/VERSION 2>/dev/null && echo "local"
# 检测 git
ls ~/.claude/skills/qingsheng-skill/.git 2>/dev/null && echo "git-managed"
```

### Step 2：读取当前版本

```bash
cat ~/.claude/skills/qingsheng-skill/VERSION 2>/dev/null || echo "unknown"
```

### Step 3：检查远端最新版本

```bash
curl -fsSL https://raw.githubusercontent.com/tomwong001/qingsheng-skill/main/VERSION 2>/dev/null
```

如果当前版本 == 远端版本：告知用户已是最新，结束。

### Step 4：执行升级

**Git 管理的安装（有 .git 目录）**：
```bash
git -C ~/.claude/skills/qingsheng-skill pull --ff-only
```

**Vendored 安装（无 .git）**：
```bash
# 下载最新 tarball 并替换 skill/ 目录
TMP=$(mktemp -d)
curl -fsSL https://github.com/tomwong001/qingsheng-skill/archive/refs/heads/main.tar.gz \
 | tar -xz -C "$TMP" --strip-components=1
cp -r "$TMP/skill/"* ~/.claude/skills/qingsheng-skill/skill/
cp "$TMP/VERSION" ~/.claude/skills/qingsheng-skill/
cp "$TMP/CHANGELOG.md" ~/.claude/skills/qingsheng-skill/ 2>/dev/null || true
rm -rf "$TMP"
```

### Step 5：读取 CHANGELOG，汇报改动

```bash
cat ~/.claude/skills/qingsheng-skill/CHANGELOG.md | head -60
```

从 CHANGELOG 中提取本次升级的变更，用中文 3-5 条 bullet 告知用户。

### Step 6：更新版本记录

```bash
cat ~/.claude/skills/qingsheng-skill/VERSION > ~/.qingsheng/installed-version
date -u +%s > ~/.qingsheng/last-update-check
```

# Autopilot 模式指南

`/自动` 触发此文件。AI 接管对话节奏，生成可直接发送的消息序列。

---

## 消息输出格式

所有 autopilot 输出必须使用标准化标签：

```
[发送] 消息内容（纯文本，可直接复制发送）
[等待 X分钟/小时] 发送时机
[等她回复]
[观察] 等待她回复后再决定下一步
```

**硬性规则（违反即判失败）**：
- 有合适消息时，第一行是无条件的 `[发送]`，不把第一条消息放进 if/else 分支；若对方拒绝或证据不足以决定下一步，先用 `[观察]` 说明需要等什么
- `[发送]` 内的文字不含括号注释（不写"（微笑）""（停顿）"）
- **`[发送]` 消息内禁止使用 Markdown 格式**：不用 `**加粗**`、不用 `—` 破折号、不用 `·` 列表
- **`[发送]` 消息内禁止策略注释**（不写"（接下来准备推邀约）""（制造神秘感）"之类）
- 每条 `[发送]` 都是独立的消息，不是一段对话的描述
- 时机控制很重要——不要秒回
- 不确定最优路径时：**选最可能成功的路径直接执行**，其他路径放备选分支

---

## 对话树格式

autopilot 模式下不只给一条消息，给接下来 3-5 轮的规划：

```
[发送] 第一条消息
[等她回复]

如果她热情回复（超过 15 字，主动问问题）：
 [等待 5分钟]
 [发送] 接话内容

如果她敷衍回复（1-3 字，没问题）：
 [等待 2小时]
 [发送] 换话题 / 制造悬念

如果她 24 小时不回：
 [等待 48小时]
 [发送] 轻松新话题（不提上条消息）
```

---

## 节奏控制规则

**回复速度**（模拟真人）：
- 她秒回 → 等 3-8 分钟再回
- 她 10-30 分钟后回 → 等 5-15 分钟再回
- 她几小时后回 → 等 1-2 小时再回
- 不要比她回得快（除非你们在实时对话中）

**消息频率**：
- 同一天内不主动发超过 2 条（她没回的情况下）
- 不要晚上 11 点后发第一条消息
- 周末/节假日可以更轻松活跃

**消息长度**：
- 正常互动：1-3 句，不超过 80 字
- 讲故事/有趣内容：可以稍长，但必须有"钩子"结尾
- 绝对不发长篇表白/解释

---

## 安全边界：必须暂停，通知用户

以下情况自动暂停 autopilot，等用户介入：

1. **她明确拒绝或要求停止联系**（"别烦我了"、"我有男友"、"不想联系"）
2. **涉及见面时间地点的确认**（约好了具体时间/地点，需要用户自己确认）
3. **她发送明显敏感内容**（如不雅图片、暴力内容——注意：普通亲密对话/性话题讨论不算，这是 escalate 阶段的正常进展，不要暂停）
4. **对话超过 10 轮没有实质推进**（需要用户评估策略）
5. **她问起真实个人信息**（职业/家庭/具体地址等需要用户自己回答）
6. **出现情绪化对话**（她在哭/发泄/需要安慰，AI 不适合替代真人）

暂停时输出：
```
⚠️ 暂停：[原因]
建议你自己处理：[具体建议]
恢复 autopilot 输入 /自动 继续
```

---

## 平台适配

**微信**：
- 消息可以稍长，支持语音/图片互动
- 朋友圈互动（点赞/评论）不算"发消息"，可以独立于消息节奏
- 适合发有内容的朋友圈（配合 autopilot 使用）

**探探/Tinder**：
- 前 3 条消息决定成败，节奏要快
- 核心目标：2-3 轮内转移到微信/手机号
- 第 1 条：有趣开场 → 第 2 条：制造共鸣 → 第 3 条：加微信

**Soul**：
- 文字质量比速度重要
- 可以比其他平台回复更慢、更有深度

**Bumble**：
- 她必须先发，你等她
- 她发了之后第一条回复要有趣，给她继续聊的理由

## 当前支持范围（基础版）

autopilot 基础版支持：
- [x] 生成对话树（3-5 轮规划）
- [x] 标准化消息输出格式
- [x] 节奏控制建议
- [x] 安全边界检测

当前环境提供 computer use 且用户已指定软件和对象时：
- [x] 可按 `user-context.md` 的「素材采集」自行定位对应会话，滚动核对发言人和时间线，再更新对话树；看不到的历史不猜
- [x] 可根据已核实的上下文草拟 `[发送]` 消息；标签表示建议，不表示消息已发出
- [ ] 不持续后台监听或自行执行整棵对话树。只有用户明确要求相应动作时，才按实际权限发送、点赞、关注或修改资料；每次操作后读回确认结果

# 心态与元策略概念库

用户问"我该有什么心态""我总是紧张"类问题时读取此文件。这些概念是所有话术的底层操作系统——心态不对，话术再好也白搭。

---

## 一、核心心态

**奖品心态**
你不是在追求女人，你是女人需要赢取的奖品。互动的潜台词从"她喜不喜欢我"变成"她够不够格"。这种心态会自动改变你的肢体语言、语速、话题选择——不是表演出来的，而是渗透到所有行为里。
用法：当你发现自己在讨好、揣摩、等回复时，提醒自己：你是奖品，她才是追求方。
注意：心态是内在的，对外说"我是奖品"是蠢的。

**游戏心态**
把追求视为一场游戏，不是生死大事。没戏了当积累经验，有戏了享受过程。这种心态让你自然而然地不在乎结果——而"不在乎"本身就是吸引力。
用法：下次搭讪或发消息前，把心理状态调整为"我在做一个有趣的实验"，而非"我必须成功"。

**多线并进**
把所有注意力压在一个人身上，必然心态扭曲、行为变形。同时和 3-5 个处于不同阶段的对象互动，不是不专一，是保持正常心态的工具。
用法：如果你发现自己在等她一条消息等到刷新手机，就是线太少了。

**好人陷阱**
女性口头说要温柔体贴的男生，但对百依百顺的男生没有吸引力。吸引力来自于对方感到你可能随时离开、你有自己的判断和底线。过度付出不等于被喜欢，等于被分类到"好朋友"。
用法：减少主动请客、送礼、嘘寒问暖的行为，在关系尚未确立之前尤其如此。

---

## 二、接近与开场

**接近焦虑**
看到喜欢的人想上前又退缩，是进化留下的保护机制，不是性格缺陷。这种焦虑不会被"勇气"覆盖，只能通过重复接近来脱敏——就像怕高的人越回避越怕，越接触越正常。
用法：头三秒内不要给自己时间"想想再说"——想了就不会行动了。3 秒法则的核心不是速度，是切断思考的时间窗口。

**三秒法则**
看到目标 3 秒内必须启动行动，不是因为 3 秒有什么魔力，是因为超过 3 秒大脑会开始找理由退缩。这是整个泡学体系中被最多独立来源验证的单一法则。
用法：不用想开场说什么，先移动脚步，内容可以到了再说。

**孔雀理论**
在高竞争场合（酒吧、派对、陌生场合），穿戴一件夸张但得体的单品（醒目的帽子、独特的戒指、有故事的外套）能制造话题切入点、吸引目光，让对方主动问而非你主动解释。
用法：选一件"有故事"的东西，不是为了好看，是为了给对方一个开口的理由。

---

## 三、吸引力机制

**预选效应**
其他女性对某个男性展示兴趣时，会让新目标自动提升对他的评估——这是进化出来的省力机制，借用别人已完成的筛选结果。
用法：和女性朋友一起出现在社交场合比单独出现更有效；让目标看到其他女性跟你互动。
注意：不要刻意表演，人能感知到刻意。

**猫绳理论**
追求的核心不是持续靠近，而是拉近-拉开的动态平衡。一直在眼前的东西没有价值，完全消失的东西会被遗忘。目标是让对方总处于"他在不在呢"的微微悬念里。
用法：不要每条消息秒回，不要总主动找话题，偶尔消失 1-2 天再出现效果比每天在线好。

**TLIF：想法转化为感觉**
爱意不是直接产生的，而是由大脑持续出现的"想法"逐步积累转化而来。女性越频繁地想到你（好奇也好、轻微烦躁也好），情感就越容易发展。所以制造悬念、留下未完成的话题比刻意表现好感更有效。
用法：不要在一次对话里把所有话都说完，留 1-2 个"下次再说"的钩子。

**坏男孩吸引力**
不可预测、有点危险感、情绪刺激能力强的男性，触发了女性进化层面上对优质基因的判断机制。注意：不是真的坏，而是表现出"你不能完全控制我"的信号。
用法：不要总是配合对方的节奏，偶尔打破预期；表现出自己有自己的事情和原则。

## 四、框架与影响

**假性时间限制**
开始互动时加一句"我只有两分钟"或"我朋友在等我"，会让对方放松警惕（不用担心你会赖着不走），更容易开放地交流。实际上你可以继续待着，时间限制只是心理润滑剂。
用法：每次线下搭讪都加上这句话，是缓解对方防御感最简单有效的技术。

**骄傲风趣法**
单纯傲慢会显得不安全，单纯幽默会显得无害。两者结合——用夸张自信的口吻开玩笑——同时传递出高价值和智慧，是许多天然高手无意识使用的核心技巧。
用法："我是全上海最帅的男人……不过今天因为昨晚没睡好，屈居第二。" 公式：高价值宣言 + 幽默解构。

**投资原则**
人对自己投入越多的东西，主观价值越高。让对方为你付出（思考、帮忙、决策），远比你为她付出更能建立吸引力。
用法：让她帮你参谋、推荐、决定——哪怕这件事你自己能决定。"你帮我选，你眼光好"比"我请你吃好的"效果要好。

**七小时法则**
从认识到发生亲密关系，平均需要约 7 小时的累计相处时间。这 7 小时可以分散在多次见面、电话、视频里，不用一次完成。过早推进会触发防卫，导致对方事后反悔或消失。
用法：别着急。第一次见面的目标不是升级，是创造"第二次见面"的理由。

**人际证据法则**
女性会通过观察目标男性与其他人的互动（朋友、服务员、其他女性），间接评估他的价值。你怎么对待旁人，比你怎么对待她更能说明你是什么人。
用法：在约会中，与服务员、朋友的互动方式要自然、大方、有幽默感。

# 平台差异化指南

不同社交平台有不同的生态、用户群体和玩法。给建议时必须考虑平台特性，不能一套话术打天下。

---

## 1. 微信

**平台特点**：熟人社交为主，最私密的聊天场景。加到微信意味着关系已经有一定基础。

**用户画像**：所有人都用，没有特定画像。关键看怎么认识的（线下认识/其他平台转过来）。

**Profile 优化：**
- 头像：清晰的生活照，最好有场景感（旅行、运动、社交场合），不要证件照或过度 P 图
- 昵称：简洁真实，不要火星文或非主流符号
- 朋友圈封面：有品味的生活照，不要默认图
- 个性签名：简短有趣或留空，不要鸡汤

**朋友圈经营（核心阵地）：**
- 频率：一周 2-3 条，不要刷屏也不要完全空白
- 内容组合：40% 生活日常 + 30% 兴趣爱好 + 20% 社交场景 + 10% 工作/学习
- 配文简短有趣，不写长篇大论
- 照片质量 > 数量，一条 3-6 张为佳
- 不要全是自拍，不要全是美食，要有层次感

**聊天风格：**
- 微信聊天偏日常、私密，语气可以更自然放松
- 可以用表情包，但不要表情包轰炸
- 语音适合关系更近之后使用，刚认识别发
- 朋友圈互动是很好的破冰工具：精准评论 > 点赞

**开场白策略（从其他平台转过来后）：**
- "微信加上了 👋 我是 [名字/平台上的昵称]"
- 直接从之前平台上聊的话题接着聊
- 评论她朋友圈作为切入点

---

## 2. 探探

**平台特点**：左滑右滑的匹配机制，双向选择。匹配 = 双方都觉得对方照片还行，有基本的外貌吸引力基础。

**用户画像**：20-35 岁为主，目的多样（恋爱、交友、约会）。用户对照片第一印象非常敏感。

**Profile 优化（照片是王道）：**
- 第一张照片决定生死：清晰的半身或全身照，自然光，微笑或自然表情
- 照片组合建议：1 张好看的正面照 + 1 张生活场景照 + 1 张社交/运动照 + 1 张展示兴趣的照片
- 不要：过度 P 图、健身房镜子自拍、墨镜遮脸、合照里看不出哪个是你
- 签名：简短有趣，一句话展示你的特点。"会做饭的程序员" > "随缘认识新朋友"

**特有功能玩法：**
- 超级喜欢：谨慎使用，用在真正心动的人身上，配合好的开场白效果翻倍
- 真心话：轻松有趣的互动方式，适合破冰
- 不要右滑每一个人，平台算法会降低你的推荐权重

**开场白策略：**
- 从她的照片或签名找切入点，越具体越好
- "你那张在 [地方] 的照片是什么时候拍的？那里好好看" > "你好，可以认识一下吗"
- 幽默型："右滑你的时候手速太快差点把手机甩出去 😂"
- 尽快转到微信，探探上聊太久容易被遗忘

---

## 3. 陌陌

**平台特点**：基于地理位置的社交，有直播、群组等社区功能。社交氛围比探探更直接。

**用户画像**：用户目的比较多元，从交友到恋爱到娱乐都有。

**Profile 优化：**
- 照片要求同探探，但陌陌用户对真实感更看重
- 个人资料填完整，职业、兴趣标签都填上
- 动态（类似朋友圈）要经营：发有趣的日常内容，让访客看到你是个有生活的人

**特有功能玩法：**
- 附近的人：可以看到距离，如果距离很近可以作为约见面的话题
- 动态互动：评论她的动态比直接私信更自然
- 群组：加入兴趣群组，在群里先混个脸熟再私聊

**聊天风格：**
- 陌陌用户整体风格偏直接，不用太绕弯子
- 但"直接"不等于"粗鲁"，依然要有分寸
- 开场白可以稍微大胆一点，但要有趣不要油腻

**开场白策略：**
- 地理位置切入："你也在 [区域]？这边有家 [具体店] 你去过没"
- 动态切入：评论她的动态内容
- 直接但有趣："你的 profile 信息量好大，让我猜猜你是做什么的"

---

## 4. Soul

**平台特点**：灵魂社交，匿名头像（系统生成的卡通头像），强调内在匹配而非外貌。有语音匹配、灵魂测试等功能。

**用户画像**：偏年轻，很多文艺、内向型用户。更看重聊天质量和精神契合度。

**Profile 优化：**
- Soul 头像是系统生成的，不能自定义，所以签名和个人简介很重要
- 签名要有个性，展示你的灵魂特质："白天写代码晚上写小说的矛盾体"
- 广场动态要用心写，Soul 用户吃文字内容
- 兴趣星球/标签选择要真实，因为系统会基于这些匹配

**特有功能玩法：**
- 语音匹配：很好的破冰方式，声音好听是加分项
- 灵魂测试：测试结果可以作为聊天话题
- 群聊派对：语音群聊，可以展示幽默感和社交能力
- 瞬间（动态）：写走心的内容比发照片更受欢迎

**聊天风格：**
- Soul 的氛围更文艺、更走心，聊天节奏可以慢一些
- 深度话题在这个平台上更受欢迎（价值观、人生思考、创作等）
- 不要太功利（快速要微信、约见面），享受灵魂交流的过程
- 表情包可以用，但文字质量更重要

**开场白策略：**
- 从灵魂测试结果切入："你的测试结果说你是 XX 型，我觉得挺准的，你觉得呢？"
- 从她的广场动态切入，评论有深度的内容
- 语音匹配后直接聊："刚才语音聊得还不错，你声音好听 😄"
- 不要直接发"你好可以认识一下吗"，太没灵魂了

---

## 5. Bumble

**平台特点**：女生先开口的机制。匹配后必须女生先发第一条消息（24 小时内），否则匹配失效。

**用户画像**：整体质量较高，很多留学生、外企白领、国际化背景的用户。对 profile 质量要求更高。

**Profile 优化（非常重要，因为你不能主动开口）：**
- 照片：高质量、自然、有生活感。第一张必须是清晰的个人照
- Bio 要写好：简短有趣，给她一个开口聊天的"钩子"
 - 好的 bio："会做意大利面但只会做一种 | 周末在哪个公园都能找到我 | 正在学冲浪，目前战绩 0 胜 12 负"
 - 差的 bio："想找一个温柔善良的女生" / 空白
- 兴趣标签：选跟你真实匹配的，不要全选
- 提示问题（Prompt）：选有趣的问题，给出有个性的回答

**特有功能玩法：**
- 女生先开口 = 你的 profile 是唯一的武器。她不开口你啥也做不了
- Extend（延长匹配时间）：谨慎使用，只对特别想聊的人用
- SuperSwipe：比探探的超级喜欢更贵，更要慎用
- 视频聊天：Bumble 内置视频通话，适合见面前先视频熟悉

**聊天风格：**
- Bumble 用户整体更注重平等和尊重
- 聊天风格可以稍微正式一点，但依然要有趣
- 很多用户会用英文或中英混搭，根据对方调整
- 不要急着要微信，Bumble 本身的聊天功能够用

**应对策略（因为是她先开口）：**
- 她开口通常比较简单（"hi""你好""你的 bio 很有趣"），你的第一次回复很关键
- 不要只回一个"谢谢"或"你好"，要接住话题并延伸
- 如果她用你 bio 里的内容开场，顺着聊并反问她
- 示例：她说"你冲浪战绩 0 胜 12 负也太真实了😂" → "哈哈是真的，但我觉得重点不是输赢，是每次被浪拍翻之后站起来假装很酷的样子 🏄 你有没有什么学了很久还是菜的技能？"

---

## 6. 青藤之恋

**平台特点**：主打高学历社交，需要学历认证（本科及以上）。用户群体学历普遍较高，社交目的以认真恋爱为主。

**用户画像**：985/211/海归/研究生及以上为主。用户更看重教育背景、职业发展和三观匹配。整体更理性、更注重长期关系。

**Profile 优化：**
- 学历认证是核心优势，务必完成认证，认证后的可信度和曝光量大幅提升
- 照片：干净得体，学历高的用户对照片的"品味感"更敏感。不要过于花哨
- 个人介绍：可以适度展示学术/职业背景，但不要变成简历。加入生活化的内容平衡
 - 好的："清华计算机毕业，但最大的成就是学会了做红烧肉 | 周末跑步看展读闲书"
 - 差的："985本硕，年薪XX万，有房有车"（太功利了）

**特有功能玩法：**
- 学历筛选：对方能看到你的认证学历，这本身就是展示面
- 匹配推荐：平台的算法会基于学历、年龄、地区推荐，保持活跃度能提高曝光
- 话题广场：参与话题讨论展示见解，比直接私信更自然的接触方式

**聊天风格：**
- 整体偏理性和深度，这个平台的用户更吃有思想深度的对话
- 可以聊职业规划、学术经历、读书、旅行等话题
- 幽默依然重要，但要"聪明的幽默"而不是"搞怪的幽默"
- 不要炫耀学历或收入，让这些通过对话自然展示

**开场白策略：**
- 从她的教育/职业背景切入（但不要面试式）："看到你也是学 [专业] 的，我一直好奇做这个方向的人平时是什么状态"
- 从共同兴趣切入："你也喜欢 [某本书/某个展]？巧了，我上周刚看完"
- 用有见地的观点引起兴趣："最近在想一个问题 [有趣的问题]，想听听你的看法"
- 不要用"你好我是XX大学毕业的"当开场白，太直白了

---

## 跨平台通用原则

1. **尽早确认平台**：信息采集时问清"你们在哪个平台聊的"，不同平台策略差异很大
2. **转平台时机**：从约会平台转到微信是一个升级信号，但不要太急。聊得来了再提，自然地说"微信聊方便一点，加一下？"
3. **Profile 是静态展示面**：在匹配/被动等待的平台（探探、Bumble、青藤之恋），profile 质量直接决定你的机会多少
4. **适配语言风格**：Soul 偏文艺、Bumble 偏国际化、青藤偏知性、陌陌偏直接、微信偏日常——跟着平台氛围走
5. **不要跨平台搜索对方**：她在探探匹配了你不代表你可以去微博找她，这很 creepy

# 展示面诊断指南

`/展示面` 触发此文件。有截图直接分析；缺少素材时先确认平台，电脑端 computer use 可按 `user-context.md` 的「素材采集」自行定位本人主页并读取，无需用户先打开该页面。确实无法访问时再请用户补截图或文字。本人展示面只更新用户档案，不新建目标档案。

---

## 诊断流程

**第一步**：确认平台（微信/探探/Tinder/Soul/陌陌/Bumble/青藤之恋）
**第二步**：收集材料（用户提供的截图，或自行找到的本人头像、动态/朋友圈、个人简介；看不到的不猜）
**第三步**：按平台维度打分（见下）
**第四步**：输出评分 + 3个最大问题 + 具体改进方案 + 改进前后对比示例

输出格式：
```
平台：xxx 总分：x/10

各维度：
- 头像：x/10 — [诊断]
- 简介/Bio：x/10 — [诊断]
- 内容/动态：x/10 — [诊断]

三大问题：
1. ...
2. ...
3. ...

具体改法：
1. [可直接执行的行动]
2. ...

朋友圈/动态内容比例建议（微信/陌陌必须输出）：
生活 40% + 兴趣爱好 30% + 社交 20% + 工作 10%

改进示例：
改前：[原内容]
改后：[建议版本]
```

---

## 微信

**展示面 = 头像 + 个性签名 + 朋友圈**

**头像评分维度（/10）**
- 清晰度：能看清脸，非背影/侧脸/戴口罩/风景代替
- 状态感：自然不做作，有活力或有故事感（旅行、运动、聚会）
- 印象分：第一眼想不想点进去看

**朋友圈内容比例（最近30条）**
理想比例：生活40% + 兴趣爱好30% + 社交20% + 工作10%
红线：纯鸡汤/广告/转发 > 50%，说明没有真实生活；全是工作/打卡 > 60%，显得无聊。

**朋友圈内容质量**
- 加分：有故事的照片（"昨晚做了一道失败的烤鸭"比"美食打卡"好）
- 加分：偶尔展示社交活动（你在聚会，不是在家刷手机）
- 加分：有自己观点的评论/转发（体现有独立思想）
- 减分：自拍超过60%（显得自恋）
- 减分：频繁发无聊的日常流水账

**个性签名**
- 好：留有好奇心的一句话（"在想一个问题"、"最近在学攀岩，比我以为的难"）
- 差：鸡汤句子、空着、工作头衔

---

## 探探 / Tinder

**展示面 = 照片组合 + 简介**

**照片策略（6张）**
- 第1张（封面）：清晰正脸，自然微笑，环境有故事感；绝对不用合照/背影/戴墨镜
- 第2-3张：展示生活方式（运动/旅行/爱好的行动照，不是摆拍）
- 第4张：社交照（和朋友/聚会，证明你不是宅男）
- 第5-6张：可以放正脸特写 + 一张能展示身材/体型的全身照

**绝对禁止**：镜子自拍、侧脸、车里自拍、健身房镜子、抱孩子照

**简介（探探/Tinder）**
- 字数：50-120字，太短无聊，太长没人读
- 公式：一个具体细节的生活描述 + 一个轻幽默 + 一个开放式邀约
- 示例：`爬山路上会找路的那种人 | 做饭一般但摆盘很好看 | 你愿意尝尝我的"美食"吗`
- 禁止：罗列标签（"爱旅游爱美食爱运动"=等于没说）

---

## Soul

**展示面 = 文字 + 声音 + 人设一致性**

Soul 的核心逻辑：深度 > 外表，文字质量决定匹配质量。

**自我介绍**：要有一个有趣/反常的细节，不能是"喜欢音乐电影美食"
**语音片段**：音质清晰，语速适中，内容有点故事感（不要直接读自我介绍）
**发帖内容**：观点型 > 日记型。"我发现有个规律：……你们有同感吗？"比"今天天气很好"好

---

## 陌陌

**展示面 = 头像 + 动态 + 附近展示**

和微信类似但更直接。附近功能重要——多发带位置感的动态，证明你是真实活跃的本地人。

---

## Bumble

**展示面 = 照片 + Prompt回答（让她主动发消息的关键）**

Bumble 的特殊性：女生第一条消息决定一切。你的任务是给她一个"忍不住回复"的钩子。

**Prompt 回答公式**：用具体、有点反常的内容制造好奇心
- 差：`我的爱好是旅行和健身` 
- 好：`我在成都学了三个月做泡菜，现在完全停不下来`

**最后一张照片**：加上 prompt "如果你不知道说什么就从这里开始↑"配上一个有争议性的细节照片（书架/奇怪的收藏品/有故事的地方）

---

## 青藤之恋

**展示面 = 学历认证 + 深度内容**

这个平台用户期待真诚和深度。

- 认证学历：强烈建议，是这个平台的信任锚
- 自我介绍：要比其他平台更有深度，可以分享一个人生观或正在思考的问题
- 不要过度包装：这个平台的用户对表演型简介敏感

---

## 通用红线（任何平台）

1. 头像是多年前照片 → 真实见面落差感，直接损害信任
2. 简介全是标签 → 没有记忆点
3. 社交媒体完全空着/锁着 → 显得有秘密或无聊
4. 所有照片都在家/室内 → 生活圈子太窄的信号
5. 配图是车/名表/豪华酒店（没有你自己）→ 显得不安全感强

# 挽回与冷激活手册

`/挽回` 触发此文件。两种模式：
- **冷激活**：聊天冷场了 / 被已读不回 / 消失了一段时间
- **关系挽回**：分手后想恢复 / 被拉黑 / 闹矛盾后冷却

---

## 第一步：诊断类型

**基于已有信息立即诊断，不要先问完再给建议。** 有什么信息就用什么信息，不确定的地方可以给"如果是X则Y"的分支。

**冷场判断**（选这个如果）：
- 还没在一起，只是联系变少了
- 对话从热络变成了敷衍
- 她不主动联系，但偶尔还回消息
- 被已读不回超过 3 天

**关系挽回判断**（选这个如果）：
- 正式分手了
- 被明确拒绝（"我们不合适"、"别再联系我了"）
- 被拉黑或删除

---

## 模式 A：冷激活

### 为什么冷场

通常是以下原因之一：
1. **需求感过高**：消息太密、追得太急，她感受到压力
2. **聊天枯燥**：停留在寒暄层面，没有情绪波动
3. **她在观望**：有其他选择，在比较；或最近生活里有事
4. **单方向付出**：你总在主动，她没有投入成本

### 冷激活策略

**第一步：停止主动，冷 3-7 天**
不发消息，不赞朋友圈，不刷存在感。这是建立"失去感"的唯一方式。

**第二步：发一条重新激活消息**
原则：有趣 > 有意义。不要发"最近还好吗"，发一条她能接住的内容。

好的重新激活消息特点：
- 与她有关的具体细节（"上次你说想去那个展，结果我昨天去了"）
- 有趣/意外的内容（"刚刚发生了一件事，只有你能理解"）
- 留有好奇心（不把故事讲完，让她问）

差的重新激活消息：
- "好久不见，最近怎么样？" — 毫无吸引力，无从接
- "你是不是生我气了？" — 暴露在意，强化弱势位置
- 解释或道歉（除非你真的做了什么值得道歉的事）

**⚠️ 给激活消息时的强制要求**：无论知道多少细节，必须在当次回复中给出一条**具体的、可直接发送的激活消息文字**。信息不完整时用"如果她喜欢XXX，可以发：…"的格式给出；不能以"等我知道更多再给你消息"为由推迟。

**第三步：这次对话目标是"留个钩子"，不是"立刻推进"**
重新联系上后，不要立刻说"我们见一面吧"。先恢复聊天节奏，再约见面。

---

## 模式 B：关系挽回

### 先做可能性评估

**高可能（值得尝试）**：
- 分手原因是环境/时机问题（异地、忙、压力）而非性格不合
- 她在分手后还有主动联系你的行为
- 关系持续时间超过 3 个月，有真实情感积累

**低可能（通常不建议）**：
- 她明确说"不合适"、"不喜欢你了"、"喜欢别人了"
- 分手因为出轨或严重信任破裂
- 她已经快速开始新关系
- 分手是因为你的行为让她感到不安全/被伤害

**如果是低可能**：最好的挽回是"体面离开" — 展示接受、不纠缠、继续生活。这才是唯一可能让她日后重新评估的路。

### 挽回时间线

**分手后第 1-14 天：绝对冷静期**
- 不联系、不出现、不刷存在感
- 不通过共同朋友传话
- 不发带情绪的消息（"我很难受"、"你后悔吗"）
- 这段时间你唯一要做的是：让自己变好（运动、社交、做有意义的事）

**分手后第 15-30 天：可以试探性联系**
- 一条轻松、无压力的消息（不提分手，不谈感情）
- 如果她回了，保持轻松聊天，不表明来意
- 如果她没回，再等 2 周

**时机成熟后**：不是告白，而是见面
- "偶尔"出现在她可能在的地方，自然遇到
- 或者："我刚好在附近，要不要一起吃个饭？"（不是"我们谈谈"）
- 见面时的目标是让她重新感受到你的吸引力，不是解释、道歉、争论分手原因

### 挽回中最常见的错误

| 错误行为 | 为什么错 |
|----------|---------|
| 反复表白感情 | 确认了你处于弱势，让她确定了"分手是对的" |
| 送礼/请客 | 讨好行为强化了你在乎她多于她在乎你的认知 |
| 问"你还有没有感情" | 让她被迫说出"没有"，等于强迫她说出分手的理由 |
| 通过朋友打探 | 暴露你在关注她，消除悬念 |
| 发情绪化长文 | 高需求感的最强信号 |

### 亲密边界 — 关系恢复后同样适用

关系重建不代表自动同意进一步亲密。对方口头说不、犹豫、沉默或身体退缩时，先停止相关动作；不要因她没有推开就认为可以继续，也不要几分钟后自行重试。以后是否继续，以双方新的、明确且自愿的表达为准。

## 示例对话

**她主动提出分手时**
> 她："我觉得我们不合适，分手吧。"
> → "好。"
> 为什么：任何挽留都是弱势信号。平静接受制造真实的"失去感"，是极少数可能让她重新评估的路径。

**再次遇见曾冷处理你的人**
> 场景：上次她不回消息，现在偶然见面。
> → 完全不提之前的事，话题转向轻松有趣的内容，表现得什么都没发生。
> 为什么：提了只会让你看起来一直在等；淡然处理反而让她重新评估。

## 自动识别与加载流程

每次用户开始聊天时，执行：

1. **检测目标身份** — 从用户消息中提取人名、代号、称呼或上下文线索
2. **匹配已有档案** — 列出已有的目标档案，尝试匹配（怎么列取决于你的运行环境，参见「持久化」）
3. **确认身份**：
 - 匹配成功 → 加载档案，输出状态摘要 + 未完成的 action items："兄弟，你说的是{称呼}对吧？上次的情况是{摘要}。你之前说要{未完成的建议}，执行了吗？效果怎么样？"
 - 不确定 → 问用户确认
 - 新目标 → 创建新档案，进入信息采集流程
4. **对话结束时更新档案** — 阶段变化、新增信号、时间线、建议记录、引领规划

1. **保存当前目标的完整状态快照**（正在进行的引领规划、未完成的建议）
2. **加载新目标的档案**
3. **输出新目标的状态摘要**，简短确认后继续

- 已知信息不能矛盾（除非用户纠正）
- 建议要有延续性：上次建议"先冷两天"，这次先追踪效果再给新建议

## 持久化 — 全局统一路径

**存储根路径**：
- macOS / Linux：`~/.qingsheng/`
- Windows：`$APPDATA/.qingsheng/`

这是**跨 agent、跨项目、跨会话**都能找到的统一位置。不再让用户选路径，原因在下面。

### 目录结构

```
~/.qingsheng/
├── user-profile.md # 用户档案（自己的情况）
├── targets/ # 每个目标一个文件
│ ├── Judy.md
│ ├── 咖啡店女生.md
│ └── ...
├── installed-version # setup 脚本写的，别动
└── last-update-check # preamble 写的，别动
```

### 为什么不再 AskUserQuestion 问路径

实测发现用户**根本不在意存哪**，只在意"我能不能看到"。之前让用户点选路径反而：
- 在第一轮对话前打断节奏
- 用户选完一头雾水，不知道刚选了什么
- Cursor/Codex 的原生记忆区路径用户根本不熟，选了也找不到

改成默认 `~/.qingsheng/` + **明确告知路径** 后：
- 无需用户操作，Skill 直接建档
- 路径固定，跨 agent 一致（Claude Code / Cursor / Codex 都能找到同一个目录）
- 用户想看随时 `open ~/.qingsheng/` 或 `cat ~/.qingsheng/targets/Judy.md`

### 素材采集：截图与电脑端自动查找

保留原有的平台、对象和关系背景引导，已知信息不重复问。有截图或聊天文字就直接使用；用户没有截图、无法截图或材料不全时，若电脑端提供 computer use，可自行去用户指定的软件中找资料，无需用户先打开精确页面或逐步教你点击位置。

- **先定位软件和对象**：通过可用的应用/浏览器入口找到相应软件，在已登录界面里利用搜索、联系人或已有聊天匹配用户给的昵称、备注或线索。确认是同一人再读取聊天和资料；出现重名或多个可能账号时，只问一个用于区分的问题。
- **再找相关资料入口**：根据实际界面的搜索框、头像、联系人卡片、个人主页或资料标签导航，必要时滚动并截图读取。微信可从联系人或聊天打开头像/资料，再查看该对象的朋友圈入口（当前客户端能访问且任务需要时）；其他软件按实际可见入口探索，不硬套微信路径。不熟悉软件本身不是让用户截图的理由。本人展示面则定位当前登录用户的主页。
- **核实并收束**：核对页面所属人、发言人和时间范围，只采集建档所需信息；资料够用就停止。记录明确写出的年龄、职业、兴趣等，不从头像、昵称或礼貌回复推断。关系背景和本人经历看不到时仍向用户补问。
- **确实读不到再回退**：应用/网页不可访问、需要用户完成登录，或搜索和相关资料入口都无法取得所需信息时，说明卡在哪，让用户完成登录或提供最少的截图/文字。手机内容未呈现在电脑上时，仍由用户手动提供素材。

这些查找、打开页面和截图操作属于用户请求的资料采集，无需逐个点击再确认；遵守用户明确限定的范围，不扩展到无关人物或会话。建档过程中不发送消息或修改资料。档案只保存必要的文字摘要，不另存原始截图或私聊全文；未知字段留空，没有实际写入时不声称已建档。

### 建档流程

**首次建档**（`~/.qingsheng/user-profile.md` 不存在）：

1. Bash 创建目录：`mkdir -p ~/.qingsheng/targets`
2. 创建 `~/.qingsheng/user-profile.md`（用档案模板，能采集到的信息都填上）
3. 只有当前确实有可辨认的目标对象时，才创建 `~/.qingsheng/targets/{称呼}.md`；本人展示面只需用户档案
4. 告诉用户："建好了，你的档案在 `~/.qingsheng/`，想看随时打开。"

**新目标建档**（user-profile.md 已存在，但这个女生是第一次聊）：

1. 确认称呼（优先昵称或特征代号，如"咖啡店女生"；只有用户明确选择真名时才用真名）
2. 创建 `~/.qingsheng/targets/{称呼}.md`
3. 告诉用户："建好了，存在 `~/.qingsheng/targets/{称呼}.md`，以后说 `/复盘 {称呼}` 就能调出来。"

**老目标回来**（`~/.qingsheng/targets/{称呼}.md` 已存在）：
- 直接读取档案，输出上次进度摘要，继续。不重复建档。

### 称呼确定策略

- 用户说了名字/昵称 → 优先用昵称或代号；真名只有用户明确选择用于文件名时才用
- 只有代号（"那个女生"）→ 问 AskUserQuestion 给 2-3 个候选
- 用户发了截图里有名字 → 默认建议昵称或代号；只有用户明确选择真名时才写入档案名

### 兜底规则

- **不要**让用户自己输入路径——默认 `~/.qingsheng/` 就够了
- **不要**在没建档的情况下先给分析（这是 SKILL.md 「第负一步 Gate A」的硬门）
- Windows 环境 Bash 用 `$APPDATA/.qingsheng/` 替代 `$HOME/.qingsheng/`（检测 `uname -s` 是 MINGW*/MSYS*/CYGWIN*）
