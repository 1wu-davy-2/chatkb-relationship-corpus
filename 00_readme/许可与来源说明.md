## 1. 三个层次的权利归属

| 层次 | 谁拥有权利 | 本仓库做了什么 | 你能做什么 |
| --- | --- | --- | --- |
| 原创层 | 仓库所有者 | 撰写、编辑、分类 | 见 `LICENSE`：默认**全部保留**，禁止抓取/搬运/训练 |
| 第三方开放内容 | 原作者 / 原机构 | 归档 + 保留署名 + 记录来源 | 按**其原始许可**使用（本仓库不额外授权，也不能收紧） |
| 第三方受限内容 | 原媒体 / 商业平台 | 只保存**短摘录**并标注出处 | 阅读原文请走来源链接；不要转载摘录 |

关键点：**本仓库的专有许可只约束原创层**。它不试图、也无权限制 CC BY-SA 的维基条目、CC BY 的开放获取论文、公有领域古籍或政府公开文件——那些内容本来就允许传播，条件是保留署名与许可声明。

## 2. 署名是怎么落在文件里的

`02_text/` 下每个 `.txt` 都以固定头部开始，`---` 之后才是正文：

```
TITLE: <标题>
SOURCE: <来源类型>
URL: <原始链接>
LICENSE: <许可名称>
LICENSE_URL: <许可链接>
ATTRIBUTION: <署名行，维基条目专用>
RETRIEVED: <UTC 抓取时间>
TOPICS: <主题标签>
MODE: full | excerpt        （仅中文官方/媒体文件）

---

<正文>
```

`05_manifest/records/*.json` 是同样信息的机器可读版，额外含 `raw_bytes`、`text_chars`、`text_sha256`。要对外分享任何一篇，**头部与 record 必须一起给出**。

`04_chunks/chunks.jsonl` 的每个片段都带 `doc_id / source / license / license_url / url / topics / excerpt_only`，因此投喂检索系统后仍能回溯到许可与出处。`excerpt_only: true` 的片段是受限摘录，**不要**再分发。

## 3. 各类来源的具体依据

- **开放获取论文（`02_text/europepmc/`）**：只抓 Europe PMC 标记为 Open Access 且许可属于 CC BY / CC BY-SA / CC BY-NC / CC BY-NC-SA / CC BY-NC-ND / CC0 / 公有领域的记录；许可字符串取自检索结果，逐篇写入文件头。NC / ND 条款意味着**不得商用、不得改后分发**——本仓库只做本地归档与检索，不改写正文。
- **中文维基百科（`02_text/zh_wikipedia/`）**：CC BY-SA 4.0。要求署名 + 相同方式共享。文件头写明条目名、链接、许可与抓取时间。若你要二次传播，必须继续以 CC BY-SA 4.0 提供，并保留署名行。
- **官方公开文件（法律、行政法规、司法解释、政府公告）**：属官方公开文件，各文件标注发布机关与链接。`02_text/zh_official/` 中 `MODE: full` 的是全文，`MODE: excerpt` 的是媒体/机构文章的短摘录（版权归原权利人）。
- **公版书籍（`02_text/gutenberg/`）**：来自 Project Gutenberg，正文在美国属公有领域。文件头保留 Gutenberg 许可链接，并注明「再分发前请自行确认所在法域的版权期」。挑选时排除了露骨情色类古籍与儿童教养类读物。性主题这一层补的是**学术史**而非消遣读物：Havelock Ellis《Studies in the Psychology of Sex》卷 1–6、《Sex and Society》《Taboo and Genetics》《The Social Emergency: Studies in Sex Hygiene and Morals》《Homo-sexual Life》，合计约 7.5 MB。这些书写于各自时代的道德与医学框架内（部分立场今天看是错的），观点不代表本仓库，作为「人们如何理解性与亲密」的一手材料保留。玄学主题在 Gutenberg 上**没有**拿到书：检索到的 numerology / astrology / fortune-telling 候选要么是《圣经》数字占卜一类的宗教语文学，要么是动物民俗，人工复核后全部由 `tools/prune_books.py` 删除——这一层的英文证据改由 Europe PMC 的 belief facet 与中文维基条目承担。
- **开源 Skill 仓库（`02_text/skills/`）**：仅当仓库带 MIT / Apache-2.0 / BSD / CC0 等宽松许可时保存全文；许可不明的一律只存 README/SKILL 的短摘录，并在文件里标注原因（`LICENSE: no_license_found`、`excerpt_only: true`）。此外**不做无差别收录**：恋爱教练类仓库常把操控技巧写成独立参考文件，`tools/fetch_zh.py` 会按文件丢弃（见第 4 节），保留下来的文件在头部 `POLICY_DROPPED:` 字段里逐个列出。

## 4. 内容筛选与删除记录

抓取不等于收录。以下过滤在脚本里执行，删除动作有对应脚本可复现：

- `tools/fetch_europepmc.py`：标题硬过滤（基因组学、动物行为、肿瘤、药理、材料等）、未成年人相关研究过滤、主题锚点匹配、非强相关标题需要摘要自带恋爱/约会语境才通过。性与玄学两批新 facet 带来一类新噪声——生物学意义的 "asexual / sexual genes / parasites"、工程意义的 "numerology"、疾病队列研究里的 sexuality 次要结局，因此硬黑名单加了 `algae / plasmodium / gametocyte / parasite / virulence / knockout / endometriosis / arthroplasty / perinatal / cardiovascular / surgery residents` 等词。刻意保持窄：不用 `alg\w*`（会杀掉 "dating app algorithms"、"divorce prediction algorithms"），不用裸 `bacterial`（STI 与约会行为研究），不用 `domestication`（伴侣想象力的质性研究）——这三条误伤在第一轮扫描里被逐条核对后撤回。
- `tools/prune_offtopic.py`：对漏网的非主题论文（动物求偶、基因、药物、职场运营类）按 PMCID 清单删除 record + 原始 XML + 清洗文本，三者同步，避免清单与磁盘不一致。`--scan` 用**当前**的标题过滤器复查已入库记录，`--scan --apply` 才删除；黑名单每次收紧后都先跑一遍 dry scan，逐条看命中标题再决定是否删。
- `tools/dedupe_wiki.py`：删除「两个不同请求标题重定向到同一条目」的维基文本与记录。另修掉一条抓取缺陷：`wiki_search_title()` 原本允许前缀式模糊命中，于是 威廉·马斯特斯 → 威廉姆斯车队（F1 车队）、上升點 → 上升2号（山峰）被当成目标条目下载过；现在只接受去空白、去消歧后缀后**完全同名**的搜索结果，宁可 missing 也不存错文章。2026-10-26 把 272 条维基标题逐条对过一遍，又清掉 17 条**早期模糊命中留下的错文章**（压力→压强、幸福→最具幸福感城市评选、应对→国务院联防联控机制、单恋→电影《蓝天下的单相思》、互惠→互惠生、顺从→女性顺从、拒绝→色情性拒绝、金融素养→金融科技、辩证行为疗法→辩证法、心理健康素养→心理師、内疚→幸存者内疚、婚俗→印度教婚俗、婚姻市场→婚姻監禮人、戈特曼→英王约翰、物质主义→後物質主義、人际距离→条目本身叫人际吸引（改 slug 为 `interpersonal_attraction`）、自恋型人格障碍重复收录）。其中四条用 `probe_wiki_titles.py` 验过替代标题后原 slug 重抓（心理压力、幸福、因应、暗恋），其余没有可用的中文条目，删除后由同一主题的其他材料承担；同时补进 5 条核实过的条目（應激、社会排斥、人际吸引、性別認同、跨性別）。DROP 字典里每个 slug 都写了原因，删除动作可复现。
- `tools/prune_books.py`：Gutenberg 挑选的人工复核清单，按原因分组删除 record + 书文件 + 记录（露骨情色、儿童性教育读物、语文学噪声）。28402 *The Sexual Life of the Child* 就是靠这条规则剔的——标题命中「成年人限定」底线，同时把 `child / children / adolescent / juvenile / infant` 加进了 `EN_BLOCK`，防止同类书再次进入。
- 两个诊断脚本让「不收」这个决定有依据：`tools/probe_wiki_titles.py` 在把条目写进 `WIKI` 之前先确认中文维基真的有这个条目（缺失只打印 MISSING，不会退而求其次抓相近文章——`爱情三角理论`、`上升点`、`马斯特斯和约翰逊` 都没有独立条目）；`tools/diagnose_facets.py` 在一个主题 facet 抓到 0 篇时打印每条候选**卡在哪一道闸门**，据此判断是该改查询（`birth_date_mate` 的 `TITLE_ABS:"born in"` 全是人口学与儿科噪声，换成 `TITLE:astrology + TITLE:mate` 就干净了）还是该接受空结果。
- `tools/fetch_books.py`：`ZH_INCLUDE / EN_INCLUDE` 白名单 + `BLOCK / EN_BLOCK` 黑名单（露骨情色古籍、历史语文学出版物、儿童教养读物）+ `SKIP_IDS`（同一部书的重复版本只留一份）。
- `tools/fetch_zh.py`（Skill 部分）：三层过滤，都在下载阶段生效，被丢弃的文件**连 `01_raw/` 都不写入**。
  1. `SKILL_SKIP_RE` 跳过仓库管线文件（`docs/`、`evals/`、`CHANGELOG`、`robots.txt`、`requirements.txt`、OG 图规范、营销文案等）；`SKILL_TRANSLATION_RE` 跳过 README 的小语种翻译副本（同一份介绍重复 5 遍没有信息量）。
  2. `MANIP_MARKERS` + `MANIP_DROP_THRESHOLD`：命中「服从性测试 / 废物测试 / 冷读 / 推拉 / 欲擒故纵 / kino / 进挪 / 打压 / negging」等词达到 3 次的文件整份丢弃。`qingsheng-skill` 因此去掉了 `skill/SKILL.md`、`advanced-techniques.md`、`signals-tools.md`、`stages.md`、`README.md` 五个文件；`partner-skill`（关系质量指数、依恋与爱的语言框架）20 个文件全部通过。
  3. `SKILL_MANUAL_DROP`：密度低于阈值但性质相同的文件人工剔除。`qingsheng-skill` 的 `examples-library.md` 里把「她笑着推开」解释成可以继续接触的信号，属于把抗拒当同意，已整份删除。
  - 另：`Mayuqi-crypto/HowToGetAlongWithGirls` 已从 `SKILL_REPOS` 移除（无许可证文件，而其 README 短摘录把「识别废测」「废物测试」当卖点），仓库里不再有该文档；`tools/fetch_zh.py` 里保留了移除原因。过滤后若一个文件都不剩，脚本不会写入空文档与空记录。
- `tools/fetch_zh.py`（性与玄学两层的挑选口径）：百科条目只收**机制与事实**（性反应周期、性功能与障碍、安全性行为、避孕、HIV、性治疗、无性恋、色情使用；黄道十二宫的天文学、占星术史、生肖与黄历、巴纳姆/福勒效应、确认偏误、冷读术、塔罗与算命产业报道），不收任何「怎么让她服从」的内容；官方/媒体层里玄学部分全部是**监管与揭批**类文献（市场监管总局关于占卜经营的定性、新华与中青报对玄学消费与「运势付费」的报道、高校开设的婚恋课公告），性部分全部是**公共卫生文件**（艾滋病防治条例与实施方案、婚前医学检查规范）。商业媒体文章一律 `MODE: excerpt`（≤1800 字）并保留来源链接。
- `tools/check_policy.py`：扫描 `03_notes/`、`02_text/skills/`、`02_text/zh_official/` 是否出现操控话术、群体决定论、未成年人、胁迫、贬义标签。**命中不等于违规**——脚本打印上下文，人工确认它出现在「不要这样做」的警示语境里才算通过。公版古籍不在扫描范围内：`骚 / 贱` 等字在文言文里高频且与内容立场无关，扫出来只有噪声。最近一次扫描（2026-10-26，维基层清理后重跑）：笔记与 Skill 合计 26 处（`03_notes` 24 + `02_text/skills` 2），全部为否定或警示用法（例如 `09_实战示例与练习.md` 把「捞女」明确标成**错误示范**，`11_星座生肖与玄学话题.md` 的「冷读」出现在解释骗局的段落）；`zh_official` 的 80 处绝大多数是法条里的「未成年人保护」条款。

## 5. 如何核验

```bash
# 全库清单（每行一个文档：来源、许可、字节数、主题、链接）
.venv/Scripts/python.exe tools/report.py

# 看某一类的许可分布
.venv/Scripts/python.exe -c "import json,collections,pathlib;\
r=[json.loads(p.read_text(encoding='utf-8')) for p in pathlib.Path('05_manifest/records').glob('*.json')];\
print(collections.Counter(x.get('license','?') for x in r).most_common())"

# 抽查任意一篇的头部署名
head -12 02_text/zh_wikipedia/attachment_theory.txt
```

`05_manifest/report.json` 里的 `by_license_documents` 就是许可分布的权威结果；`05_manifest/manifest.jsonl` 与 `sources.csv` 是全库清单（CSV 可直接用表格软件打开）。

## 6. 如果你想删除某一篇

1. 删 `05_manifest/records/<doc_id>.json`；
2. 删该 record 里 `raw_path` 与 `text_path` 指向的两个文件；
3. 重跑 `tools/build_corpus.py`（会重建 `04_chunks/chunks.jsonl`）；
4. 重跑 `tools/report.py` 刷新统计。

不要只删文本不删 record——清单与磁盘不一致会让后续投喂出现空引用。
